# Resume Module — Use Cases

## UC-01: Создание резюме вручную
**Актор:** CLIENT (авторизован)
**Предусловие:** кол-во резюме < 2, есть ClientProfile

**Сценарий:**
1. /resume → кнопка «Создать с нуля»
2. Создаётся Resume (status=DRAFT) → редирект /resume/builder/[id]?step=1
3. Шаги 1–7: пользователь заполняет секции, автосохранение каждые 2с (updateSection)
4. Шаг 2 — кнопка «Заполнить из профиля» подтягивает данные из ClientProfile
5. Шаг 3 (О себе) — кнопка «Сгенерировать» → AI возвращает 2 варианта → пользователь выбирает → запись в AiGenerationLog
6. Шаг 8 (Финал) — запускается анализ → сохраняется ResumeAnalysis → показывается скор
7. «Опубликовать» → status=PUBLISHED, is_active=true

**Альтернативы:**
- Закрыл вкладку → черновик сохранён, при возврате продолжает с того же шага
- AI недоступен → блок подсказок скрыт, заполнение вручную
- Нажал «Назад» → предыдущий шаг, данные сохранены

**Ошибки:**
- Уже 2 резюме → кнопка неактивна, тултип «Удалите одно из резюме»
- Нет ClientProfile → редирект /profile + «Сначала заполните профиль»

## UC-02: Импорт резюме из PDF
**Актор:** CLIENT (авторизован)
**Предусловие:** кол-во резюме < 2

**Сценарий:**
1. /resume → «Импорт из PDF» → /resume/import
2. Пользователь загружает PDF (макс. 5 МБ)
3. Клиент валидирует тип/размер → отправляет на сервер
4. Сервер: PDF → текст → AI парсинг → структурированные данные
5. Лоадер «Анализируем...» (5–15 сек)
6. Создаётся Resume (DRAFT) + ResumeSections из распознанных данных
7. Редирект в конструктор с предзаполненными полями

**Ошибки:**
- PDF защищён паролем или скан → «Не удалось прочитать PDF. Загрузите текстовый PDF»
- Файл > 5 МБ или не PDF → клиентская ошибка до отправки
- AI вернул пустой результат → создать пустое резюме, предложить заполнить вручную

## UC-03: Создание резюме гостем
**Актор:** GUEST

**Сценарий:**
1. /resume → «Попробовать без регистрации»
2. Конструктор работает с localStorage (не БД)
3. ИИ доступен с лимитом: 1 запрос на секцию
4. Шаг «Финал» → «Скачать PDF» доступно без входа
5. «Сохранить» / «Опубликовать» → модалка «Войдите или зарегистрируйтесь»
6. После авторизации → данные из localStorage мигрируют в БД

**Альтернативы:**
- Закрыл браузер → данные в localStorage, восстанавливаются при возврате
- Очистил localStorage → данные потеряны (ожидаемо, предупреждение в UI)

## UC-04: Редактирование резюме
**Актор:** CLIENT (авторизован)

**Сценарий:**
1. /resume → «Редактировать» на карточке
2. Создаётся новая версия (version+1, status=DRAFT), опубликованная не трогается
3. Конструктор открывается с текущими данными
4. «Опубликовать» → новая версия активна, старая → ARCHIVED

**Альтернативы:**
- Не сохранил → черновик висит, опубликованная версия не изменилась

---

## UC-05: Скачать PDF
**Актор:** любой (гость или авторизованный)

**Сценарий:**
1. Кнопка «Скачать PDF» в конструкторе или на странице резюме
2. POST /api/resume/[id]/export с текущими секциями
3. Сервер рендерит HTML-шаблон → генерирует PDF
4. Файл возвращается как blob → браузер скачивает
   Имя файла: `resume-[desired_position]-[YYYY-MM-DD].pdf`

**Ошибки:**
- Генерация провалилась → toast «Ошибка генерации, попробуйте позже»

## UC-06: Удаление резюме
**Актор:** CLIENT (авторизован)

**Сценарий:**
1. «Удалить» → confirm-диалог «Удалить резюме? Нельзя отменить»
2. Подтверждение → status=ARCHIVED (soft delete)
3. Лимит: было 2/2 → стало 1/2

## UC-07: ИИ-генерация текста секции
**Актор:** любой (гость: лимит 1/секцию, авторизованный: 3/секцию)

**Сценарий:**
1. Кнопка «Сгенерировать» в секции (О себе, Опыт, Обязанности)
2. Клиент отправляет: desired_position + заполненные секции + тип секции
3. Сервер → промпт → AI API (streaming) → 2 варианта текста
4. Пользователь выбирает → текст вставляется в поле
5. Авторизованным: запись в AiGenerationLog

**Ошибки:**
- Превышен лимит → кнопка заблокирована, тултип «Лимит запросов исчерпан»

---

## UC-08: Анализ резюме
**Актор:** CLIENT (авторизован)

**Сценарий:**
1. Автозапуск на шаге 8 или вручную кнопкой «Проанализировать»
2. Все секции → AI API с промптом-оценщиком
3. AI возвращает JSON:
   `{ score_total, score_completeness, score_structure, score_keywords, score_skills, recommendations[], trending_skills[] }`
4. Сохраняется ResumeAnalysis → отображается пользователю
5. При каждой публикации — пересчитывается

**Альтернативы:**
- Заполнено < 40% → предупреждение «Заполните больше для точного анализа», анализ всё равно запускается
